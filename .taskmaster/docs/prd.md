# PRD: 바이브 코딩 컨설팅 회사 홈페이지

## 1. 개요

| 항목 | 내용 |
|------|------|
| 문서명 | 바이브 코딩 컨설팅 회사 홈페이지 PRD |
| 작성일 | 2026-09-24 |
| 버전 | v1.1 (DRAFT) |
| 목적 | 바이브 코딩 컨설팅 회사를 소개하고, 잠재 고객이 컨설팅을 문의할 수 있는 회사 홈페이지 구축 |

## 2. 배경 및 목표

- 바이브 코딩(Vibe Coding) 컨설팅을 제공하는 회사의 대외 소개용 웹페이지가 필요하다.
- 방문자가 회사를 빠르게 이해하고, 컨설팅 프로세스를 파악하며, 문의를 남길 수 있도록 하는 것이 핵심 목표다.
- 이번 버전은 **정적 소개 + 프로세스 안내 + 문의 폼(실제 발송 없음)** 범위로 한정한다.

## 3. 대상 사용자

- 바이브 코딩 컨설팅에 관심이 있는 예비 고객(개인/기업)
- 회사 소개와 컨설팅 서비스, 진행 방식을 검토하려는 방문자

## 4. 디자인 방향

- **톤**: 모던하면서 깔끔한 느낌
- 여백을 넉넉히 활용한 미니멀 레이아웃
- 과한 장식 요소(그림자, 그라디언트, 애니메이션) 배제, 타이포그래피와 여백으로 완성도 표현
- 컬러: 무채색(화이트/그레이/블랙) 기반 + 포인트 컬러 1개(브랜드 컬러) 조합 권장
- 폰트: 가독성 좋은 산세리프 (예: Pretendard, Inter 등)
- 반응형: 데스크톱/태블릿/모바일 대응 필수

## 5. 기술 스펙

| 항목 | 내용 |
|------|------|
| 프레임워크 | Next.js (App Router 기준) |
| 배포 | Vercel |
| 스타일링 | Tailwind CSS 권장 (모던/깔끔한 톤 구현에 적합) |
| 라우팅 | Next.js 파일 기반 라우팅 (`/`, `/contact`, `/process`) |
| 백엔드 연동 | 없음 (문의 폼은 클라이언트 유효성 검사만 수행, 실제 서버 전송 없음) |
| 이미지 | Next.js `Image` 컴포넌트 사용, 슬라이드용 이미지 3장은 `public/` 폴더에 배치 |

## 6. 범위 (Scope)

### 포함
1. 메인 페이지
2. 컨설팅 문의 페이지
3. 컨설팅 프로세스 페이지

### 제외 (Out of Scope)
- 실제 폼 발송/이메일 전송 로직 (백엔드 연동 없음)
- 회원가입/로그인
- 결제/가격 페이지
- 다국어 지원
- CMS 연동 (콘텐츠는 코드 내 하드코딩)

## 7. 페이지별 요구사항

### 7.1 메인 페이지 (`/`)

**목적**: 방문자에게 회사를 짧고 명확하게 소개한다.

| 구성 요소 | 요구사항 |
|-----------|----------|
| 이미지 슬라이드 | 페이지 최상단에 배치. 이미지 3장을 자동/수동 전환하는 슬라이드(캐러셀) 형태. 좌우 이동 버튼 및 하단 인디케이터(dot) 포함 |
| 회사 소개 섹션 | 회사명, 한 줄 소개 문구, 간단한 설명(바이브 코딩 컨설팅이 무엇인지, 회사가 제공하는 가치) |
| 내비게이션 | 헤더에 메인/컨설팅 프로세스/문의하기 페이지로 이동하는 메뉴 |
| 문의 유도 | "컨설팅 문의하기" 버튼 → 컨설팅 문의 페이지로 이동 |
| 반응형 | 데스크톱/모바일 화면에서 슬라이드 및 텍스트가 깨지지 않아야 함 |

**허용 기준(Acceptance Criteria)**
- [ ] 페이지 진입 시 이미지 슬라이드가 최상단에 노출된다
- [ ] 슬라이드는 3장의 이미지를 순환하며 보여준다
- [ ] 회사 소개 텍스트(이름/한 줄 소개/설명)가 슬라이드 하단에 노출된다
- [ ] "컨설팅 문의하기" 버튼 클릭 시 문의 페이지로 이동한다
- [ ] 헤더 내비게이션으로 프로세스/문의 페이지 이동이 가능하다
- [ ] 모바일 너비(약 400px)에서도 레이아웃이 정상적으로 표시된다

### 7.2 컨설팅 문의 페이지 (`/contact`)

**목적**: 방문자가 연락처를 남겨 컨설팅을 문의할 수 있는 화면을 제공한다. **단, 실제 발송(이메일/서버 전송)은 동작하지 않아도 된다.**

| 입력 항목 | 필수 여부 | 유효성 검사 |
|-----------|-----------|-------------|
| 이름 | 필수 | 빈 값 불가 |
| 전화번호 | 필수 | 숫자/하이픈 형식 (예: 010-1234-5678) |
| 이메일 | 필수 | 이메일 형식(@ 포함) 검증 |

| 구성 요소 | 요구사항 |
|-----------|----------|
| 문의 폼 | 이름, 전화번호, 이메일 입력 필드 + "문의하기(발송)" 버튼 |
| 제출 동작 | 실제 서버 전송/이메일 발송은 구현하지 않음. 클라이언트 측 유효성 검사 후, "문의가 접수되었습니다" 등의 안내 메시지(alert 또는 화면 내 메시지)만 표시 |
| 뒤로가기 | 메인 페이지로 돌아가는 링크/버튼 제공 |

**허용 기준(Acceptance Criteria)**
- [ ] 이름/전화번호/이메일 입력 필드가 제공된다
- [ ] 필수 항목이 비어있거나 형식이 올바르지 않으면 제출 시 에러 메시지가 표시된다
- [ ] 모든 항목이 올바르면 제출 시 성공 안내 메시지가 표시된다 (실제 발송 없음)
- [ ] 메인 페이지로 돌아갈 수 있는 링크가 있다

### 7.3 컨설팅 프로세스 페이지 (`/process`)

**목적**: 컨설팅이 어떻게 진행되는지 방문자가 한눈에 이해할 수 있도록 단계별로 보여준다.

| 구성 요소 | 요구사항 |
|-----------|----------|
| 프로세스 단계 목록 | 컨설팅 진행 단계를 순서대로 표시 (예: ① 상담 신청 → ② 요구사항 진단 → ③ 컨설팅 방향 제안 → ④ 실행/코칭 → ⑤ 결과 리뷰). 단계 수와 명칭은 초안이며 실제 운영 프로세스에 맞춰 조정 가능 |
| 시각적 표현 | 타임라인 또는 스텝 카드 형태로 단계를 시각화 (아이콘 + 번호 + 제목 + 짧은 설명) |
| 문의 유도 | 페이지 하단에 "컨설팅 문의하기" 버튼 배치 |

**허용 기준(Acceptance Criteria)**
- [ ] 컨설팅 진행 단계가 순서대로 시각적으로 표시된다
- [ ] 각 단계별로 제목과 짧은 설명이 함께 제공된다
- [ ] 페이지 하단에서 문의 페이지로 이동할 수 있다
- [ ] 모바일 화면에서 단계 목록이 세로로 자연스럽게 쌓인다

## 8. 비기능 요구사항

- 정적 페이지 수준의 가벼운 구현 (별도 백엔드/DB 불필요)
- 최신 데스크톱/모바일 브라우저에서 정상 동작
- Vercel 배포 기준 빌드 성공 및 페이지 로딩 속도 확보 (불필요한 대용량 이미지 지양, Next.js Image 최적화 활용)
- 페이지 간 이동은 Next.js `Link` 컴포넌트로 처리

## 9. 향후 고려사항 (본 버전 제외)

- 실제 문의 폼 발송 기능(이메일 전송 API, 서버/DB 연동)
- 컨설팅 사례/포트폴리오 페이지
- 고객 후기 페이지
- 블로그/인사이트 콘텐츠 페이지

## 10. 열린 질문 (확인 필요 시 메모 추가)

- 회사명 및 로고, 슬라이드용 이미지 3장은 별도로 준비되어야 함 (현재는 placeholder 사용 가능)
- 포인트 컬러(브랜드 컬러) 지정 필요
- 컨설팅 프로세스 단계 수 및 실제 명칭 확정 필요 (현재는 5단계 예시)
